# 输出形态

> 为什么 pory 的输出长现在这样。相关：[设计说明](design.md)

终端里一次调用的完整形态：

```
↳ hello world                                  ← 原文回显：只在管道 / 文件输入时（最淡）
你好世界                                        ← 译文：stdout，终端里加粗
◈ zh-CN ⇄ en · mymemory · 1 block · cache 0/1   ← 元信息：stderr，始终贴在屏底
```

三层亮度，各有分工：

| 部分 | 走哪条流 | 说明 |
|---|---|---|
| 原文回显 | stderr | **只在输入来自管道 / 文件时出现** —— 终端手打时原文还挂在提示符上，重复一遍没意义 |
| 译文 | stdout | 终端里**加粗、不上色**；**重定向到文件时一个字都不带** |
| 元信息 | stderr | `◈` 起头，然后是 语向 · 后端 · 块数 · 缓存 |

## 为什么译文不上色

提示符本来就是彩色的，译文再用强调色就会和命令行糊在一起（`$Pory 你好` 是青的、
译文也是青的，分不出哪行是敲的哪行是结果）。换成素色加粗之后反而是
「彩色提示符 vs 素色译文」，一眼分得开，而且**不必猜用户的提示符配色** ——
换任何主题都不会撞。**颜色留给状态**（回退的琥珀）。

## 对齐栅格

**左侧的符号全部落在第 0 列，内容从第 2 列开始。** `◈` `↳` `⚠` 和动画的 `⠋`
都是 1 格宽（在字体里实测过），所以 pory 的每一条 stderr 行都和命令行文字
**同列**（常见提示符是「1 格符号 + 1 空格」）。这不是装饰，是让「pory 说的」
和「你敲的」落在同一条栅格上。

`◈` 是菱形里嵌着菱形 —— **由多边形构成的多边形**。pory 的名字来自多边兽
Porygon（`poly` 即「多边」），这个字形正是它那副多面体拼起来的样子。
挑它之前量过一圈：`△▽◁▷◇◆◊◉◎◕⊕✶` 都在字体里，`⬢⬡⎔⌬` 这些更立体的没有，
而 `◈` 是唯一在 Maple Mono NF CN / Adwaita Mono / DejaVu Sans Mono
三款等宽字体里都有、advance 又正好 600（恰好 1 格）的那个。

## 元信息里每一段都有真实含义

没有一段是凑数的：

- `⇄` 表示方向按检测结果定（互翻中）；`›` 表示方向确定
- `ai → mymemory` 表示**发生过回退**，此时整行转琥珀色 —— 静默回退是不诚实的
- `18 blocks` 是真实的切块数（400 字符一块，切分在本地完成，不依赖网络）
- `cache 12/18` 是「命中 12 块 / 共 18 块」；关闭时写 `cache off`，
  强制刷新时写 `cache refreshed`

放在译文**下方**而不是上方是有意的：长文本滚两屏也顶不掉它。

## 管道里绝对干净

```bash
pory "hello" > out.txt        # out.txt 里只有译文，一个转义码都没有
cat file.md | pory -t en      # 同上
```

加粗只在 **stdout 是终端**时才上（跟 `bat`、`ls --color=auto` 同一个做法：
有没有人在看，决定要不要打扮）。想要连脚注和等待动画都不要，用 `--plain`。

顺带一个副作用是语义变干净了：**管道里的行为默认就等于 `--plain`**。

## 等待动画

联网翻译要花时间，终端里会有一行 thinking 动画：

```
⠹ 正在翻译 2.7s
```

- 盲文点旋转（80 ms 一帧）+ 一道微光扫过文案（**只有正在移动的那几个字带颜色**）
  + 实测秒数
- **不做进度条**：我们不知道还要等多久，任何百分比都是编的。秒数则是 `Instant`
  数出来的真实耗时 —— "像 agent 在思考"和"不撒谎"在这里并不冲突
- **只在 stderr 是终端时出现**，管道 / CI / 重定向里一个字节都不多写 ——
  加这个功能之前的行为完全不变
- 缓存命中只要几毫秒，所以第一帧等 150 ms 才画：快请求根本看不到动画，不闪
- 结束时整行擦掉，不跳行、不留残影、不多一个空行
- 不开新线程：请求与计时器用 `select!` 在同一条线程里轮询，
  **结构上不可能**出现两处同时写 stderr 的撕裂

两个细节是「诚实 / 稳」压过「好看」的选择：

| 细节 | 选择 | 为什么 |
|---|---|---|
| 光标 | **不隐藏**（不用 `\x1b[?25l`） | 藏了之后若被 Ctrl-C 打断，恢复序列不执行 → 终端光标消失，得敲 `reset` 才救得回来。代价只是光标停在行尾 |
| 清行 | `\x1b[2K\r` 整行重画 | 靠补空格对齐会算错 —— `中文` 每字 2 格、秒数会涨位数，一旦算错就是残影 |

## 字体要求

**唯一的硬依赖是旋转动画那十个盲文点** `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏`：

| 缺的是 | 后果 |
|---|---|
| `⠋…` 盲文点 | 走 fallback → 字形风格不一致、宽度可能不是整数格；最坏是十个一样的豆腐块，**动画看起来像没在动** |
| `·` `›` `⇄` `↳` `⚠` | 只是难看。这五个字符都在行首或独立行，行内没有其它需要对齐的东西 → 不会错位 |

要求能压这么低，是三条设计决策的连带红利：没有跨行对齐的框线了（旧的 `┌│└`
版本才真怕字体）、重绘用 `\x1b[2K` 清行而不是补空格（对字符宽度完全不敏感）、
只用标准 16 色（没有 truecolor）。重定向输出和 `--plain` 路径是**零依赖**的 ——
一个转义码都不发，什么字体都能看。

需要提醒的是 **DejaVu Sans Mono 缺那十个盲文点**（`DejaVu Sans` / `DejaVu Serif`
有，等宽变体反而没有），而它恰好是 Linux 上最常见的兜底等宽字体。
